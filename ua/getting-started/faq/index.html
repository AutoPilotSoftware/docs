📦 Патерн 1: готові пошти (просто і швидко)

Section titled “📦 Патерн 1: готові пошти (просто і швидко)”

Найпростіший шлях — купити пакет пошт у перевіреного постачальника і одразу використовувати. Жодних налаштувань, жодної переадресації.

Де купити: KYC SHOP by NVS — пакети firstmail / notletters з готовим логіном і паролем для IMAP.

Як підключити:

  1. Купити пакет пошт у шопі
  2. У таблиці AutoPilot заповнити лише три стовпці:
    • [EMAIL] mail = адреса пошти з пакету
    • [EMAIL] mail_password = пароль з пакету
    • [EMAIL] mail_provider = firstmail / notletters
  3. Готово — переадресація не потрібна, AutoPilot читає IMAP напряму

💡 Підходить для більшості завдань — KYC на будь-якій біржі, верифікація email, реєстрації.

🍎 Патерн 2: iCloud-ферма

Section titled “🍎 Патерн 2: iCloud-ферма”

Альтернатива для тих, хто будує масштабну ферму. Використовує Hide My Email від iCloud+ — один основний inbox приймає пошту з тисячі sub-адрес.

ПлюсиМінуси
🟢 0.99$/міс → до 1000 hidden email адрес❌ Потрібен iPhone для активації iCloud+
🟢 Усі листи приходять на один основний inbox — читаєте один IMAP замість 1000❌ Apple обмежує швидкість створення (обхід — hidemyemail-generator)
🟢 Apple підписує домени — anti-spam, anti-detection
🟢 Особливо стабільно працює з Bybit

Як налаштувати:

  1. Купити iPhone + оформити підписку iCloud+ на icloud.com/icloudplus
  2. iCloud → Hide My Email → створити нові адреси (вручну або скриптом)
  3. Усі hidden emails автоматично пересилаються на основний iCloud
  4. App-Specific Password для основної пошти — support.apple.com/uk-ua/102654
  5. У таблиці AutoPilot заповнити:
    • [EMAIL] mail = hidden_xxxx@icloud.com (одна з 1000)
    • [EMAIL] mail_provider = icloud
    • [EMAIL] forwarding_mail = ваш основний main@icloud.com
    • [EMAIL] forwarding_mail_password = App-Specific Password основної пошти
    • [EMAIL] mail_forwarding_provider = icloud

Видалення адрес та ротація («крутити» ферму заново):

Слоти під нові адреси можна звільняти, але із застереженнями (перевірено за Apple Support):

  1. Видаляти можна лише деактивовані адреси — спершу Deactivate, потім Delete. На icloud.com/icloudplus → Hide My Email → адреса → Deactivate, далі внизу списку під «N inactive addresses» → Delete address.
  2. Видалення незворотне: стару адресу назад не повернути й не використати повторно — при перестворенні Apple видає нову випадкову адресу.
  3. Видалення звільняє слот: на ліміті Apple прямо пише «delete one before creating another» — видалив → можеш створити нову.
  4. Не безкінечно й не миттєво. Apple душить швидкість: ~5 нових адрес / 30 хв (× кількість членів родини), при упорі — кулдаун ~30–60 хв. М’яка стеля ~500–1000 адрес на акаунт.

⚙️ Що робить AutoPilot сам. Вбудований HME-генератор (pure-HTTP, без браузера) створює та резервує адреси з урахуванням лімітів Apple (5/30 хв, авто-кулдаун на 429). Видалення — поки вручну на icloud.com. Тобто «крутити» ферму = видалив вручну → AutoPilot догенерує нові.

📨 Патерн 3: Outlook / Hotmail через refresh-token

Section titled “📨 Патерн 3: Outlook / Hotmail через refresh-token”

Microsoft з 2024 року вимкнув Basic Auth для IMAP на персональних Outlook / Hotmail-акаунтах — звичайний пароль пошти більше не працює. Працює лише OAuth2 з refresh-токеном.

Селлери пошт (наприклад, KYC SHOP by NVS) продають Hotmail-комбо у форматі:

З усіх полів AutoPilot потрібні лише два: email та довгий токен у кінці (починається з M.).

Як підключити:

  1. Купити пакет Hotmail-комбо у шопі
  2. У таблиці AutoPilot заповнити три стовпці:
    • [EMAIL] mail = name@hotmail.com (перше поле комбо)
    • [EMAIL] mail_password = M.C510_BAY... (останнє поле — refresh-токен, не звичайний пароль)
    • [EMAIL] mail_provider = outlook
  3. Готово — AutoPilot сам визначить, що це refresh-токен (за префіксом M.), обміняє його на access-токен через Microsoft і підключиться до IMAP через XOAUTH2

🔄 Авто-оновлення: access-токен живе ~1 годину, AutoPilot оновлює його у фоні без участі пілота.

💡 Звичайний пароль теж працює для акаунтів, де Basic Auth ще не вимкнений (старі корпоративні / forwarding-пошти). Якщо пароль не починається з M. — використовується класичний IMAP з логіном/паролем.

2. 🔐 2FA: як це працює

Section titled “2. 🔐 2FA: як це працює”
  • При підключенні 2FA софт зберігає секретний ключ у стовпець [2FA] totp_secret_code
  • Цей ключ можна імпортувати в будь-який додаток: Google Authenticator, Authy, 1Password та ін.
  • AutoPilot автоматично генерує та вводить TOTP-коди за потреби
  • Для ручної генерації коду із секретного ключа: totp.danhersam.com

💾 Бекап: totp_secret_code додатково зберігається в логи профілю (папка /logs) — навіть якщо випадково очистите таблицю, секретний ключ завжди можна знайти в логах.

⚡ Автопідключення: дії whitelist та withdraw автоматично підключать 2FA, якщо він ще не встановлений. Окремо запускати 2fa не потрібно.

⏰ 2FA коди не підходять? TOTP-коди залежать від точного часу на комп’ютері. Якщо код відхиляється біржею — синхронізуйте годинник: Windows: Settings → Time & Language → Date & time → Sync now. macOS: System Settings → General → Date & Time → Set time and date automatically.

🌐 Bybit: проблеми з 2FA? Якщо код на пошту не приходить при підключенні Google Authenticator — вкажіть bybitglobal у стовпці [BYBIT] domain таблиці. У деяких регіонах bybitglobal.com працює стабільніше. Детальніше — Bybit AutoPilot → Bybit Global домени.

4. 🧩 Проксі та капча

Section titled “4. 🧩 Проксі та капча”

Стовпець [PROXY] proxy — проксі профілю у форматі ip:port:user:password

✅ Заповнювати не потрібно — AutoPilot автоматично бере проксі з вашого профілю AdsPower / Dolphin / Vision / Afina на льоту. Капча вирішується з IP профілю, щоб він збігався з IP решти трафіку. Все відбувається автоматично.

🏠 Проксі обов’язково має бути резидентським. Вбудований вирішувач надсилає перевірку капчі з IP профілю, а GeeTest не пропускає датацентрові IP — перевірка не проходить. Дешевий датацентровий проксі = стабільні падіння на капчі, навіть коли все інше налаштовано вірно.

🔄 Авторотація: дзеркала Bybit та сесії проксі

Section titled “🔄 Авторотація: дзеркала Bybit та сесії проксі”

Іноді реєстрація впирається не в акаунт, а в те, звідки ви прийшли: біржа дивиться на репутацію вихідного IP, і якщо з цієї адреси вже створювали багато акаунтів, відмова прийде ще до коду підтвердження. AutoPilot розбирається з цим сам — у два кроки.

Крок 1 — інше дзеркало Bybit. Bybit це кілька доменів, і в кожного свій захист на вході. Той самий IP, якому відмовив основний домен, часто спокійно проходить на bybitglobal.com. Раніше пілоти підставляли цей домен вручну — тепер AutoPilot перебирає дзеркала сам:

📌 Робоче дзеркало запам’ятовується. Домени Bybit — окремі біржі з окремими пулами акаунтів: акаунт, створений на bybitglobal.com, на bybit.com не існує. Тому AutoPilot записує спрацьоване дзеркало у стовпець [BYBIT] domain, і всі наступні дії за профілем ідуть туди ж. Підставляти його руками більше не потрібно.

Крок 2 — свіжа сесія проксі. Якщо дзеркала закінчилися, справа таки в адресі. У резидентських проксі номер сесії зашитий у логіні:

➕ Ланцюжки дій: кілька ACTION за один прохід

Section titled “➕ Ланцюжки дій: кілька ACTION за один прохід”

У комірку ACTION можна записати не одну дію, а цілий сценарій — кроки через +:

Кроки виконуються по черзі на кожному акаунті. Акаунти при цьому й далі йдуть паралельно (parallel_limit) — черговість діє лише всередині одного акаунта.

Навіщо це потрібно:

  • Раніше, щоб прогнати три дії на тих самих акаунтах, доводилося запускати батч тричі поспіль, щоразу чекаючи завершення та наново позначаючи профілі
  • Браузер профілю не перезапускається між кроками — одна сесія на весь ланцюжок замість трьох запусків антидетект-профілю

Налаштування в конфігу:

КлючТиповоЩо робить
combo_action_delay30,120Випадкова пауза в секундах між двома кроками одного акаунта. Менше — швидше, більше — менше схоже на бота
combo_keep_browserYESОдин браузер на весь ланцюжок. Поставте NO, якщо потрібен чистий запуск профілю на кожному кроці

⚠️ Якщо крок завершився помилкою, решта кроків цього акаунта пропускається. Інші акаунти продовжують працювати.

📝 Пробіли навколо + не важливі, регістр теж: Register + Learn = register+learn. Якщо хоча б один крок ланцюжка написаний з помилкою або недоступний на вашому тарифі — рядок не буде обраний цілком.

6.1 🤖 Розумна ф’ючерсна торгівля (futures_smart)

Section titled “6.1 🤖 Розумна ф’ючерсна торгівля (futures_smart)”

ACTION: futures_smart — автоматична торгівля ф’ючерсами з аналізом ринку, лімітними post-only ордерами та управлінням позиціями.

💰 Комісії: post-only лімітні ордери = 0.02% (maker), закриття по маркету = 0.055% (taker). Разом ~0.075% за цикл — на 32% дешевше ніж маркет ордери (0.11%).

📊 Стовпці таблиці:

СтовпецьОписПриклад
[TRADING] trading_coinМонета для ф’ючерсівBTC
[TRADING] trading_amountРозмір позиції за одну ітерацію (з урахуванням плеча) в USDT1000
[TRADING] trading_cyclesКількість торгових циклів15

🔑 Важливо: trading_amount — це розмір позиції з урахуванням плеча, а не сума реально використовуваного балансу. Реальний баланс на одну угоду = trading_amount / leverage.

📐 Формула:

  • Реальний баланс за угоду = trading_amount ÷ плече
  • Обсяг за цикл = trading_amount × 2 (відкриття + закриття)
  • Цільовий обсяг = trading_amount × cycles × 2

Приклад: trading_amount=1000, leverage=10, cycles=15

  • Реальний баланс за угоду: 1000 ÷ 10 = 100 USDT
  • Обсяг за один цикл: 1000 × 2 = 2000 USDT
  • Цільовий обсяг: 1000 × 15 × 2 = 30 000 USDT

limit_futures_iteration_wait_interval💤 Пауза між циклами, сек (мін,макс)60,180

🧠 Алгоритми визначення напрямку:

  • simple — слідує за трендом: аналіз останніх 5 свічок + ціна vs MA5 (зростання → Long, падіння → Short)
  • inverse_simple — контр-тренд: інвертує сигнал simple (зростання → Short, падіння → Long)
  • advanced — комплексний аналіз: EMA 8/21 кросовер + RSI 14 + Volume Spike (1.7x від середнього) + Funding Rate

⚠️ Ризики: ф’ючерсна торгівля з плечем пов’язана з ризиком ліквідації. Використовуйте помірне плече та невеликі суми для набиття обсягу.

💡 Порада: якщо ордер не заповнюється протягом limit_futures_order_timeout — сигнал перераховується заново. Збільшіть limit_futures_price_offset_ticks для швидшого заповнення (але з менш вигідною ціною).

7.1. 🔑 Мастер-гаманець — Авто-whitelist, $0 комісії, невідстежуваний вивід

Section titled “7.1. 🔑 Мастер-гаманець — Авто-whitelist, $0 комісії, невідстежуваний вивід”

Виводьте з сотень акаунтів не вводячи жодної адреси вручну. AutoPilot створює унікальний гаманець для кожного акаунта, сам додає його в whitelist, виводить з нульовою комісією і збирає все на ваш мастер-гаманець. Кожен акаунт виводить на свою адресу — зв’язати їх між собою неможливо.

Що ви отримуєте:

  • 🏷️ Автоматичні вайтлісти — не потрібно створювати адреси чи заповнювати таблицю. AutoPilot створює унікальну адресу для кожного акаунта і додає її в whitelist на Bybit з повним підтвердженням email/2FA
  • 🕵️ Невідстежувані виведення — кожен акаунт виводить на свою унікальну адресу. Спільної адреси немає = зв’язати ваші акаунти неможливо
  • 💰 $0 комісія за виведення — Bybit не бере плату за виведення в мережі Aptos (проти $1-2 за акаунт на ERC20/TRC20)
  • 📥 Збір в один клік — після виведення збираєте всі кошти на мастер-гаманець за секунди
  • ⚡ Миттєві переводи — кошти приходять за ~1 секунду

Як це працює (3 дії):

    • Заходить на Bybit, додає її в whitelist, підтверджує email/2FA — все автоматично

🔀 Як AutoPilot обирає антидетект-браузер

Перемикача браузера в AutoPilot немає. Антик обирається сам — за тим, як виглядає [PROFILE] profile_id у таблиці. Правила йдуть згори вниз, працює перше відповідне:

УмоваБраузер
у конфігу заданий vision_configVision (перекриває все інше)

profile_id — тільки цифри (1274563)Dolphin

💡 Антики можна змішувати в одній таблиці. Браузер обирається для кожного рядка окремо, тож в одному запуску можуть іти профілі і AdsPower, і Dolphin, і Afina. AutoPilot перед стартом перевірить, що всі потрібні програми запущені, і крутитиме профілі паралельно — скільки одразу, задає parallel_limit.

З Vision так не вийде: vision_config задається один раз на весь конфіг і перевіряється першим, тому на Vision поїдуть усі профілі з таблиці.

⚠️ Часта проблема: переплутали «Номер» та «ID». В AdsPower два різні ідентифікатори: «Номер» — порядковий, тільки цифри, і «ID» — літери з цифрами, наприклад k1b0tidb. Скопіювали «Номер» — AutoPilot бачить самі цифри і йде в Dolphin. Звідси й помилка Dolphin local server offline - Launch Dolphin then retry у людини, яка Dolphin взагалі не ставила. Потрібна колонка ID.

⚠️ Ще одна проблема: Afina без ключа. Для Afina потрібні обидві умови одразу — UUID у profile_id і afina_api_key у конфігу. Без ключа рядок не підходить під жодне правило (UUID не проходить перевірку «літери та цифри» через дефіси), і профіль іде в AdsPower. Отримаєте помилку AdsPower про профіль, якого там немає. Перевірте afina_api_key у конфігу.

AdsPower:

  • 📥 Встановіть свіжу версію SunBrowser: Налаштування → Локальні налаштування

  • ⚠️ Обов’язково вимкніть «API verification» (API & MCP → API Settings). Якщо тумблер увімкнено, кожен запит до локального API вимагає ключ, і AutoPilot не зможе запускати та зупиняти профілі. Тумблер має бути вимкнено:

Dolphin:

  • Увімкніть Profile ID: Шестерня → Customize columns → Profile ID
  • ▶️ Застосунок Dolphin Anty має бути запущений, і ви маєте бути залогінені — AutoPilot керує профілями через локальний API (порт 3001). Для автоматизації потрібна активна платна підписка (на free-плані запуск профілів через API недоступний).

    • ⚠️ Токен із шаблону конфіга — placeholder і вже прострочений. Обов’язково замініть на свій свіжий, інакше отримаєте помилки Dolphin.

18. 🛡️ VPN для пілота: системний проксі

Section titled “18. 🛡️ VPN для пілота: системний проксі”

🩺 Біль пілотів: увімкнули VPN — і проксі в антидетект-браузері перестали працювати: профілі не відкриваються, нескінченне завантаження, IP не той. У режимі повного тунелю (TUN) через VPN іде весь трафік системи, разом зі з’єднаннями антидетект-браузера з його власними проксі, — і ланцюжок ламається.

Рішення — режим «Системний проксі». VPN покриває звичайні застосунки (Chrome, Telegram, термінал, AutoPilot.exe), а антидетект-браузери й далі ходять через проксі своїх профілів: системний проксі на них не поширюється, доки ви самі не увімкнете в антидетекті опцію «використовувати системний проксі».

Крок 2. Додайте свою VLESS-підписку. Потрібне посилання-підписка від VPN-провайдера — рекомендуємо BlancVPN (VLESS + Reality, ~50 серверів, 45 країн): оформити підписку → — за цим посиланням ви отримуєте 1 безкоштовний місяць і знижку в подарунок. Скопіюйте посилання підписки, відкрийте INCY і натисніть «Вставити» (або «+ Додати») — список серверів підтягнеться сам.

Крок 3. Налаштування → З’єднання → увімкніть «LAN через проксі».

Цей перемикач поширює VLESS-проксі на локальні застосунки — на термінал, а отже і на сам AutoPilot.exe.

Крок 4. Головна → оберіть режим «Системний проксі» і натисніть кнопку увімкнення.

🔌 Якщо не вантажиться сам антидетект (панель не відкривається, ліцензія/API недоступні у вашій мережі) — спрямуйте через системний проксі службовий трафік самої програми. В Afina: Network Detection → «Use system proxy for connection», там само кнопки Detect system proxy та Test via system proxy. Через проксі піде лише трафік застосунку (API, відбитки, ліцензія) — проксі профілів лишаються недоторканими.

⚠️ Не вмикайте TUN, якщо працюєте з антидетект-браузерами — саме повний тунель ламає проксі профілів. Для AutoPilot потрібен режим «Системний проксі».
